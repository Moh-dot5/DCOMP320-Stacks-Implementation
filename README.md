# Stack-Based Expression Evaluator

**Course:** DCOMP320 – Data Structures and Algorithm
**Assignment:** Stacks Implementation (Individual, 10%)

A Python program that reads mathematical expressions from `input.txt`, evaluates each one using a stack-based approach, and writes the results to `output.txt`.

## Files

| File | Purpose |
|------|---------|
| `stack_evaluator.py` | Source code (Stack class, evaluator, file handling) |
| `input.txt` | Sample input used for testing |
| `output.txt` | Output generated by the program |
| `README.md` | This file |

## How to run

Requires Python 3.6+ (no external libraries).

```bash
python stack_evaluator.py
```

This reads `input.txt` and writes `output.txt` in the same folder. To use other file names:

```bash
python stack_evaluator.py my_input.txt my_output.txt
```

## Input file structure

- One mathematical expression per line.
- Expressions are separated by a line containing only dashes (e.g. `-----`).
- Supported: `+`, `-`, `*`, `/`, parentheses, decimal numbers, unary minus (e.g. `-3 + 10`).
- Spaces are optional. Blank lines are ignored.

Example:

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
```

## Output file structure

Same layout as the input: each expression is replaced by its result, and separator lines are kept.

```
13
-----
16
```

Whole-number results are printed without `.0` (so `13`, not `13.0`). Invalid expressions produce a line such as `Error: division by zero` or `Error: mismatched parentheses` instead of crashing the program.

## How it works

1. `Stack` class provides `push`, `pop`, `peek` (plus `is_empty`, `size`).
2. `tokenize()` splits an expression into numbers, operators and parentheses, and recognises unary minus.
3. `evaluate()` uses two stacks, one for operands and one for operators. Operators are applied when a higher- or equal-precedence operator is already waiting on the stack, and parentheses force their contents to be evaluated first (`*` and `/` bind tighter than `+` and `-`).
4. `process_file()` reads the input, evaluates each expression, and writes the output.

## Assumptions and limitations

- Only the operators `+ - * /` and parentheses are supported (no `^`, `%`, functions or variables).
- Division always gives a decimal result internally; non-whole results are rounded to 6 decimal places.
- A line made only of three or more dashes is treated as a separator, so an expression can never be written as just `---`.
- Implicit multiplication such as `2(3+4)` is not supported and is reported as an error.
